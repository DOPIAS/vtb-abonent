# Проверки

## API и PostgreSQL

Из `apps/api`:

```sh
go vet ./...
go test -race ./...
```

Интеграционные Go-тесты работают с настоящей PostgreSQL. Создайте отдельную тестовую базу и перед запуском задайте `TEST_DATABASE_URL`, например:

```sh
export TEST_DATABASE_URL='postgres://abonent:your-password@localhost:5432/abonent_test?sslmode=disable'
go test -race ./... -count=1
```

Без этой переменной PostgreSQL-сценарии пропускаются. Не используйте рабочую базу для тестов.

Проверяются авторизация и доступ владельца, переходы статусов, повторные запросы, конкурентное списание последнего занятия, расчёты обзора, согласованность snapshot и повторное создание демо-данных.

## Клиент

Из `apps/mobile`:

```sh
npm run typecheck
npm run lint
npm run format:check
npm test
npx expo-doctor
npm run export:web
```

Jest запускает отдельные окружения для React Native и браузерного календаря. Тесты покрывают формы, подтверждения, тему и хранилище, российский телефон, даты и часовые пояса, кабинет, продление пакета и публичную страницу.

## Работающий API

После миграций и запуска сервера из корня:

```sh
BASE_URL=http://localhost:8090/api/v1 make test-integration
```

Без `BASE_URL` используется API на порту `8080`. Скрипты создают собственные синтетические аккаунты и проверяют ответы по [OpenAPI](openapi.yaml). Данные сохраняются; запускайте проверки в выделенном окружении. Подробности и дополнительная SQL-инспекция — в [описании HTTP-сценариев](../tests/integration/README.md).

## Ручной сценарий

1. Войти, создать клиента и пакет на два занятия.
2. До оплаты проверить запрет проведения; затем подтвердить оплату и получить остаток 2.
3. Запланировать занятия в местном времени. Провести первое: остаток 1.
4. Перенести и отменить второе: остаток остаётся 1.
5. Исправить первое с подтверждением: остаток возвращается к 2.
6. Открыть клиентскую ссылку без входа. Проверить историю, остаток и следующее занятие.
7. Провести занятие в кабинете; убедиться, что публичная страница обновилась. Перевыпустить и отозвать ссылку, проверить недоступность старой.
8. Создать следующий пакет из обзора: условия заполнены, новый пакет ожидает оплаты. Подтверждённые оплаты и оплаченный остаток не должны увеличиться до оплаты.
9. Проверить переключение темы, сохранение выбора, российский телефон и календарь на узком экране.
10. Повторить на физических iOS/Android; отдельно проверить системный выбор даты, клавиатуру, потерю сети и повтор операции.

Веб-сборка не заменяет приёмку на телефоне. Перед размещением также нужны чистый Docker-запуск, HTTPS, проверка конфигурации секретов и резервного восстановления.
