# Интеграционные проверки

Проверки обращаются по HTTP к уже запущенному Go API и его настоящей PostgreSQL. Они не импортируют серверный код и не подменяют ответы. Требуется Python 3.10+; сторонних Python-пакетов нет.

Из корня репозитория после запуска API и миграций:

```sh
python3 tests/integration/run.py
python3 tests/integration/phone.py
python3 tests/integration/dashboard.py
```

По умолчанию `BASE_URL=http://localhost:8080/api/v1`. Для проверки через Caddy:

```sh
BASE_URL=http://localhost:8090/api/v1 python3 tests/integration/run.py
```

Если CORS настроен на другой доверенный origin, задайте `CORS_TEST_ORIGIN=https://your-dev-origin.example`. Все JSON-ответы сопоставляются с response-схемами соответствующей операции `docs/openapi.yaml`. Валидатор покрывает используемое контрактом подмножество OpenAPI, включая `$ref`, required, типы, nullable, enum, диапазоны, UUID и RFC3339; это не универсальный OpenAPI-валидатор.

Каждый запуск создаёт уникальные синтетические учётные записи `qa-<uuid>@example.com` и их данные. Проверки не удаляют существующие записи и не используют демо-учётную запись. Запускайте на локальной или выделенной тестовой системе: синтетические записи сохраняются. Токены и пароли не печатаются в результатах. Код возврата `0` означает успешное завершение всех сценариев; недоступный сервер и любая ошибка дают ненулевой код.

Дополнительная проверка хранилища требует `psql` и явного `DATABASE_URL` к той же локальной базе, которую использует API:

```sh
DATABASE_URL='postgres://abonent:your-password@localhost:5432/abonent?sslmode=disable' python3 tests/integration/storage.py
```

Замените URI на свой. Этот скрипт создаёт отдельные синтетические данные через HTTP и выполняет только SQL-чтение в `BEGIN READ ONLY`. Он проверяет хеши session/share токенов, параметры Argon2id, аудит и PostgreSQL-типы; затем отзывает только собственные ссылку и сессию. Необходимые права SQL: чтение таблиц приложения и `information_schema`.

Состав автоматических и ручных проверок описан в [руководстве](../../docs/testing.md).

Дополнительная проверка российского телефона после миграции `00002` и перезапуска API:

```sh
BASE_URL=http://localhost:8090/api/v1 python3 tests/integration/phone.py
```

Она проверяет нормализацию, недопустимые форматы и JSON-типы, сохранение/очистку номера, поиск и приватность. Создаются только отдельные синтетические данные.

`dashboard.py` проверяет суммы и округление, очередь продления по всем оплаченным пакетам клиента, расписание, исправления и изоляцию владельцев. Все три HTTP-набора можно запустить из корня командой `make test-integration`.
